# Repository Audit — 2026-09-23

## Scope

This pass reviewed the existing visual prompting repository, provider documentation, current model identifiers, reusable skills, and Supermemory routing behavior.

## Existing foundation

- four provider/model adapters
- general prompt architecture, curation, editing, image-to-prompt and typography skills
- style adapters
- real-estate specialization
- examples and research/source notes
- initial cross-model router

## Gaps found

1. Model selection existed, but skill orchestration was incomplete.
2. There was no provider-neutral Visual Brief contract.
3. There was no explicit Prompt Compiler between intent and model-specific wording.
4. Reference roles were under-specified.
5. Multi-shot video continuity was not a first-class asset.
6. QA and iteration existed unevenly.
7. Supermemory was not connected to the visual workflow as a disciplined learning layer.

## Repairs applied

Added orchestration skills:
- Visual Brief
- Model Router
- Skill Stack Planner
- Prompt Compiler
- Visual Bible
- Video Storyboard

Added general skills:
- Reference Manager
- Iteration Controller
- Quality Gate

Updated:
- main router
- all four model adapters
- README
- SKILLS_INDEX
- model capability matrix
- architecture document
- skill quality rubric
- router regression cases
- source registry

## Design decision

The system now treats model-specific prompting as compilation from a shared visual brief, rather than four isolated prompt-writing styles.

## Verification policy

Repository writes are read back after commit.
Provider behavior is checked against current provider documentation.
Durable Supermemory lessons are container-scoped and independently verified before promotion.
